# 常见问题与排障

> 本文提供用户侧的安全排障顺序；开发构建和底层日志问题见开发排障手册。
>
> 阅读时长：约 5 分钟。

## 资料库无法打开

1. 确认目录仍存在并可读。
2. 检查是否选择了正确的资料库根目录。
3. 使用界面中的重试和诊断入口。
4. 如界面提供 metadata repair，先阅读影响再确认。

不要通过删除用户文件或整个资料库目录解决元数据错误。

## 导入失败

- 查看逐项结果和错误原因。
- 确认来源文件仍存在并可读。
- 检查目标目录权限、重复文件和同名冲突。
- iCloud 文件未下载时，等待同步或按界面提示处理。
- 重试前确认最终目录没有半成品；应用应自动保持这一不变量。

## 搜索没有结果

- 清除不需要的筛选。
- 检查当前目录、标签或 Smart List 上下文。
- 区分普通搜索与语义搜索。
- 语义搜索需要可用模型和已建立的索引。

## AI 功能不可用

- 检查本地模型或远程 Provider 状态。
- 检查隐私规则是否允许当前任务。
- 确认远程凭据仍可用。
- 查看调用日志和失败回退说明。

不要在 issue、诊断或截图中公开 API key、Authorization header 或完整敏感路径。

## 外部改动未出现

- 刷新资料库状态。
- 查看 watcher 或集成诊断。
- 检查文件是否仍为 iCloud 占位符。
- 对长期未同步的状态使用界面提供的恢复或重新索引入口。

## 收集未知问题的诊断

1. 打开设置窗口的独立 Diagnostics Tab，先查看 writer、回调、丢弃计数和磁盘预算是否 degraded。
2. 需要再次复现时，开启有时限的诊断模式；不要为了排障长期保留开发者模式。
3. 问题发生后立即标记 incident，再从活动视图或 Trace Console 查看同一 trace 的步骤和失败点。
4. 保存 `.amdiagnostic` 前逐项审阅隐私选择。文件名、完整路径和 repository metadata snapshot 都需要独立决定。
5. 诊断包只保存在你选择的位置，不会自动上传。发送前仍应检查隐私报告和附件列表；当前附件只可能是你单独
   确认的 repository metadata snapshot 及其 WAL/SHM，不接受任意用户文件。
6. 收到他人诊断包时只通过应用离线打开；包按不可信输入校验，不能把其中的路径或事件当成恢复指令执行。

如果 Diagnostics 显示存储降级，事件仍可能暂存在有界内存中；该降级不会改变业务提交结果。先保存必要的诊断包，
再决定是否删除受管理本地日志。`read_only` 历史 incident 不可删除；删除入口不得用于清理资料库或修复数据库。
