# 冲突与恢复

> AreaMatrix 将同步冲突、启动恢复、资料库错误和元数据修复作为显式用户任务处理。
>
> 阅读时长：约 7 分钟。

## 同步冲突

冲突入口会显示受影响文件、候选版本、resolution 和预计副作用。选择 Keep both、替换或其他处理方式前，核对目标路径和将被保留的内容。替换类操作需要二次确认。

## iCloud 占位符

占位符未下载时，文件内容可能不可读。AreaMatrix 应显示同步或不可用状态，不把占位符当作普通完整文件。触发下载属于平台副作用，必须来自明确的产品路径。

## 启动恢复

应用启动时可能发现未完成导入、扫描会话或 metadata 状态。恢复界面会说明发现的问题、可继续的动作和重试结果。不要手工删除 staging 或数据库文件来跳过恢复。

配置、classifier、overview 和 AI 恢复留在各自页面；只有未完成的文件事务可以阻断应用进入资料库。概述
事务由 Core 根据 staging、backup 和 hash 的可验证状态决定 roll-forward 或 rollback，不让用户猜测恢复方向。
技术详情保持原文、默认折叠并可复制；无法识别的恢复动作不会显示为空按钮。界面语言变化只重新解析说明
和按钮，不改变恢复 operation、进度或草稿。

## 设置冲突

Repository 冲突保留本地草稿，并针对 dirty fields 显示原保存值、最新持久化值和本地值。用户可以放弃并
载入最新值，或审阅最新基线后再次保存；审阅本身不写入，也没有强制覆盖或静默合并。

Classifier 冲突额外冻结当前编辑语言，只比较该语言和受影响规则字段。另一语言保持只读，不能在冲突处理
中自动复制、合并或翻译。

AI 摘要保存冲突同样保留 draft。替换 user-owned 摘要前并列展示当前摘要和新 draft，并要求明确选择替换、
保留或继续编辑。

## 资料库错误

资料库无法打开时，可以：

- 重试读取。
- 查看用户可理解的错误和建议动作。
- 选择其他资料库。
- 生成 repository metadata snapshot，或从 About 导出脱敏文本诊断；导出前查看隐私说明。
- 在满足条件时进入 metadata repair。

## 元数据修复

metadata repair 只处理 `.areamatrix` 状态。确认界面必须说明影响、要求和结果。修复不得删除、移动、重命名或覆盖用户文件。

## 重新索引

重新索引根据文件系统重建或协调元数据。文件存在性、内容和位置以文件系统为准。重新索引不应用来强制恢复数据库中的旧路径。
